Terraform module for managing a single Google Cloud Pub/Sub subscription.

---

## Overview

This module creates and manages a `google_pubsub_subscription` resource on GCP. It accepts a single structured `pubsub_subscription_config` object and applies a consistent naming convention (`<project_code>-<base_name>-<location>-<environment>`). Optional features — dead-letter routing, message filtering, retention, ordering, and expiration — are conditionally applied via the same input object.

---

## Usage

```hcl
module "pubsub_subscription" {
  source = "github.com/subhamay-bhattacharyya-tf/terraform-google-pubsub-subscription"

  environment  = "prod"
  project_code = "prj-20-pubsub-16748"
  region       = "us-central1"

  pubsub_subscription_config = {
    base_name = "my-service"
    topic     = "projects/my-gcp-project/topics/my-topic"
    location  = "us-central1"

    # Optional
    ack_deadline_seconds       = 30
    message_retention_duration = "604800s"
    retain_acked_messages      = false
    filter                     = null
    enable_message_ordering    = false
    labels = {
      team = "platform"
    }
  }
}
```

## Notes & Caveats

> **Destructive operation:** Destroying this module deletes the subscription permanently. Ensure downstream consumers are stopped before running `terraform destroy`.

- `enable_message_ordering` requires the publisher to set an ordering key on messages; enabling it without ordered publishers has no effect.
- `filter` uses the Cloud Pub/Sub filter syntax (CEL subset). Invalid expressions will be rejected at apply time by the API.
- `dead_letter_policy` requires the Pub/Sub service account to have `pubsub.publisher` on the dead-letter topic and `pubsub.subscriber` on the source subscription.
- Subscription names follow the pattern `<project_code>-<base_name>-<location>-<environment>` and are immutable after creation — renaming requires destroy and recreate.

## CI / Workload Identity Federation Setup

The Terratest job authenticates to GCP via [Workload Identity Federation](https://cloud.google.com/iam/docs/workload-identity-federation). If the job fails with `Permission 'iam.serviceAccounts.getAccessToken' denied`, grant the WIF pool principal the required IAM binding:

```bash
gcloud iam service-accounts add-iam-policy-binding \
    "<service-account-email>" \
    --project="<gcp-project-id>" \
    --role="roles/iam.workloadIdentityUser" \
    --member="principalSet://iam.googleapis.com/projects/<project-number>/locations/global/workloadIdentityPools/<pool-name>/attribute.repository/<github-org>/terraform-google-pubsub-subscription"
```

| Variable | Description |
|----------|-------------|
| `GCP_PROJECT_ID` | GCP project ID passed as `GOOGLE_CLOUD_PROJECT` to Terratest |
| `GCP_PUBSUB_TOPIC` | Existing topic name passed as `GOOGLE_PUBSUB_TOPIC` to Terratest |
| `GCP_WORKLOAD_IDENTITY_PROVIDER` | Full WIF provider resource name |
| `GCP_SERVICE_ACCOUNT` | Service account email to impersonate |
